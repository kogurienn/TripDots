# TripDots 更新版

HTML / CSS / JavaScriptのみで動作する静的サイトです。React、ビルド工程、データベースは使用していません。

## 変更したファイル
- index.html：既存3件の画像を維持し、ブランドヘッダー、検索・フィルター、Leaflet地図、投稿フォーム、詳細ダイアログを構成。
- style.css：深緑を基調とした余白、写真カード、選択状態、ホバー、CTA、PC・スマホ対応。動きを減らすOS設定にも対応。
- script.js：既存3件＋保存投稿を単一のデータ源として表示。保存、重複チェック、削除、検索、動的フィルター、地図ピン・詳細の連動を実装。
- README.md：この説明を追加。
画像ファイルは変更していません。

取得したGitHub版には地図・カテゴリフィルター・投稿フォームがなかったため、今回追加しています。

## 投稿と保存
保存キーは `tripdots.posts.v1`。追加した投稿だけをJSON配列としてlocalStorageに保存します。初期3件はコードに保持します。

行き先、国、カテゴリ、季節、日数、思い出が一致する投稿を重複と判定します。全角・半角、前後の空白、連続空白、英字の大小を正規化します。画像や位置だけを変えた同内容の再投稿も防ぎます。

保存成功後だけフォームをクリアし、検索・フィルターを「すべて」に戻して新しい投稿を表示します。保存失敗時は入力を保持します。壊れた保存データは上書きせず、投稿・削除を止めてエラーを表示します。削除は自分で追加した投稿の詳細画面から行えます。初期3件は削除できません。

国は自由入力で、追加した国やカテゴリはフィルターに自動で反映します。国名の翻訳・地名検索・自動位置取得は行いません。地図クリックで緯度・経度を入力するか、手入力してください。画像は任意のHTTPS URLを使用できます。画像がない、または取得できない場合はプレースホルダーを表示します。

保存先は同じブラウザー・同じオリジンです。他ユーザーや端末とは共有しません。ブラウザーのサイトデータを消すと投稿も消えます。既存の公開サイトとローカルプレビューは別の保存先です。

## 公開方法
このフォルダーの `index.html`、`style.css`、`script.js` と `images/` を、元のGitHub Pages公開元に配置してください。画像のパスと大文字小文字を維持してください。追加のビルド設定は不要です。

GitHub Pagesがmainブランチを公開元にしている場合、mainへの反映後に公開処理が実行されます。公開状態はGitHubのPages設定またはActionsで確認してください。

Leaflet 1.9.4のみを追加しています（https://leafletjs.com/examples/quick-start/）。地図はOpenStreetMapを使用し、帰属表示を維持しています。Leaflet・地図タイル・外部画像の取得にはネット接続が必要です。Leafletの取得に失敗しても投稿・検索・詳細は使えます。

## 検証
Microsoft Edgeのブラウザー自動テストで以下を確認済みです。
- 初期3件の表示、既存検索、国フィルター、詳細
- 投稿、フォームリセット、再読み込み後の保持、正規化した重複登録の拒否
- 追加投稿の検索、カテゴリ、追加した国のフィルター、地図ピンとピンクリック詳細
- 削除のキャンセル・確定、再読み込み後の削除維持、不要になった国フィルターの除去
- 地図クリックによる位置入力、画面サイズ変更後のピン位置
- 保存容量エラー時の入力保持、壊れた保存データの保護、HTML文字列を安全に文字として表示
- PC 1440px・スマホ390px表示、横方向のはみ出しがないこと
- Leafletを読み込めない場合の案内とカード表示
JavaScript構文検証、差分の空白検証も実施しました。

## 今後データベース化する部分
1. `loadPosts()` / `savePosts()` を、投稿一覧取得・作成・削除のAPIへ置き換える。非同期通信に合わせて送信中の表示とエラー処理を追加する。
2. 投稿IDをサーバーで管理し、重複判定をサーバーの制約やトランザクションで保証する。
3. ログイン、投稿者ID、削除権限をサーバー側で確認する。
4. 画像URLだけでなく画像アップロード・保存先を用意する。
5. localStorageにある投稿の移行・バックアップ機能を用意する。
カード・フィルター・地図・詳細は共通の旅行データを使用しているため、同じデータ形式を維持すればUIは引き続き使用できます。
